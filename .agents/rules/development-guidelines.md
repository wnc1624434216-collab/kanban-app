# 看板應用 (Kanban App) 開發規範

本規範依據當前專案架構（純原生前端、零依賴、GitHub Pages 自動發布）制定，所有後續開發與 AI 協作均須嚴格遵循以下準則。

---

## 1. 專案架構與核心原則

* **純原生技術棧 (Vanilla Web)**：
  * 本專案僅使用 **HTML5**、**CSS3**、**原生 JavaScript (ES6+)**。
  * **嚴禁引入外部重型套件、編譯工具或打包器**（如 Webpack、Vite、npm packages、React、Vue 等），保持無需建置步驟、直接由瀏覽器讀取運行的特性。
* **零外部 CDN 依賴**：
  * 核心樣式與邏輯必須封裝於本地檔案中，避免網路斷線或 CDN 異常導致看板功能失效。
* **單一資料流與資料持久化**：
  * 所有資料以本地瀏覽器的 `localStorage` 作為儲存媒介。
  * 採用狀態驅動（State-driven）模式：修改記憶體中的 `tasks` 資料後，統一呼叫 `saveTasks()` 並重新調用 `renderBoard()` 進行介面重繪。

---

## 2. 檔案分工與命名規範

| 檔案路徑 | 職責定義 |
| :--- | :--- |
| `index.html` | 頁面骨架、表單結構、看板三欄容器。禁止在 HTML 內混入內聯樣式 (inline style)。 |
| `style.css` | 佈局（Grid/Flexbox）、元件色彩、陰影、過渡動畫與到期紅字標籤樣式。 |
| `app.js` | 業務邏輯、DOM 事件監聽、HTML5 Drag & Drop、日期格式化與逾期判斷。 |
| `README.md` | 專案功能與使用說明文件。 |

## 3. 程式碼規範

### 3.1 HTML 規範
* 遵循語意化標籤（`<header>`, `<main>`, `<section>`, `<form>`）。
* 所有表單欄位必須有對應的 `<label for="...">`，以兼顧無障礙性 (Accessibility)。
* 保持現有容器的 `id`（例如 `task-form`, `task-title`, `task-due-date`, `list-todo`, `list-in-progress`, `list-done`），不得隨意重新命名以避免破壞 JS 綁定。

### 3.2 CSS 規範
* 採用現代簡約設計風格，以 Slate / 灰色系為底，主色調為深藍 (`#2563eb`)。
* 狀態樣式必須明確：
  * 一般截止日期標籤：`.due-tag`（灰色背景、深色字）。
  * 今天或已逾期標籤：`.due-tag.overdue`（淡紅底 `#fef2f2`、紅字 `#dc2626`、紅邊框 `#fca5a5`）。
* 具備響應式設計（RWD），在手機等窄螢幕寬度下欄位自動換行。

### 3.3 JavaScript 規範
* **日期處理與顯示**：
  * `<input type="date">` 取得的值格式為 `YYYY-MM-DD`，於資料層保存。
  * 卡片顯示時必須使用標準「`年/月/日`（`YYYY/MM/DD`）」格式化呈現。
  * 日期逾期判定：以使用者當前本地日期的 `00:00:00` 為準。若 `截止日 <= 今天` 則判定為過期或今天（套用紅色警示）。
  * 截止日期欄位一律為**選填**，未填寫時不可顯示任何日期標籤。
* **安全性防護 (XSS)**：
  * 使用者輸入之任務標題必須使用 `textContent` 賦值，嚴禁直接使用 `innerHTML` 插入未轉義的文字。
* **拖曳 API**：
  * 使用 HTML5 原生 Drag & Drop API（`dragstart`, `dragend`, `dragover`, `drop`）。

## 4. Git 提交與發布規範

* **分支策略**：
  * 預設開發與發布分支為 `main`。
  * 任何推送到 `main` 分支的 Commit 都會由 GitHub Actions 自動觸發 GitHub Pages 部署。
* **Commit Message 規範**：
  * 建議遵循 Conventional Commits 格式：
    * `feat:` 新增功能（如新增優先級標籤、搜尋欄）
    * `fix:` 修復問題（如拖曳異常、日期計算錯誤）
    * `style:` 樣式調整（如字體大小、間距、色彩）
    * `docs:` 文件更新（如 README、規範說明）
    * `refactor:` 重構程式碼（未改變功能）

---

## 5. 功能變更驗證清單 (QA Checklist)

在每次提交前，必須在本機完成以下驗證：
1. [ ] **新增任務**：未輸入標題時無法提交；可正常輸入標題。
2. [ ] **截止日期**：
   * 不選日期：卡片正常新增，不顯示日期標籤。
   * 選擇未來日期：卡片顯示 `YYYY/MM/DD` 灰色標籤。
   * 選擇今天或過去日期：卡片顯示 `YYYY/MM/DD` **紅色**標籤。
3. [ ] **卡片互動**：卡片可在「待處理」、「進行中」、「已完成」三欄之間互相拖曳，計數數字即時更新。
4. [ ] **刪除功能**：點擊卡片右上角 `✕` 按鈕可順利刪除該任務。
5. [ ] **資料留存**：重整網頁（F5），所有任務與其所屬欄位皆正確保留。
